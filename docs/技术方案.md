## 1. 产品范围（已确认）

| 维度 | 结论 |
|---|---|
| 内容 | 多语言**原文**歌词：日语为主，也收录韩语（谚文）、中文（汉字）、英语原文歌；不做翻译对照 |
| 日语显示 | 汉字 + **按词**假名注音，默认即显示（v1 不做开关、不做罗马字） |
| 注音来源 | **全部人工标注**：在歌曲页正文书写紧凑标记（`明日{あした}から`），无自动生成 |
| 音频/时间轴 | 一律不要 |
| 规模 | 会长期持续增加 → 每歌一个独立内容文件即可扩展 |
| 用途 | 公开分享的静态站点，部署于 GitHub Pages |
| 首版功能 | 歌词展示页 + 「复制歌词」按钮（原文/纯假名/带注音）；站内搜索（M3） |

## 2. 架构（纯 Hugo，三层）

1. **内容层**：每首歌 = `content/songs/<slug>.md`。front matter 存元数据；
   正文为 `{{< lyrics >}}…{{< /lyrics >}}` 包裹的带标注歌词（shortcode 内部是原始文本，
   不经过 Markdown 加工）。
2. **解析渲染层**：`layouts/shortcodes/lyrics.html` 在模板内按 `{注音}` 规则把每行切成
   「纯文本段 / 注音段」，输出 `<ruby>` 歌词与复制数据。校验失败用 `errorf` 使构建报错并带行号；
   疑似漏标汉字用 `warnf` 提示。
3. **页面与功能层**：`layouts/songs/single.html` 提供页头与复制按钮脚本；三种复制文本
   （原文 / 纯假名 / 带注音）由模板从段结构自拼，内嵌为页面数据。

数据流一句话：

> 编辑歌曲页 `<slug>.md`（元数据 + 标注歌词）→ Hugo 构建（shortcode 解析渲染）→ 静态站

关键点：

- **为什么不需要「自定义 delimiter」**：Hugo/Goldmark 没有自定义行内语法扩展；
  但 Go 模板自带正则（`findRE`/`replaceRE`）足以解析紧凑标记，解析逻辑住在模板里即纯 Hugo。
- **为什么歌词放 content/ 而非独立源文件**：Hugo dev server 监听 content/，
  改歌词保存即自动重建刷新；shortcode 承载正文不会让原始文本被发布成独立文件。
- **加一首歌 = 新建一个 `<slug>.md`**，不新增模板。

## 3. 内容组织

- `content/songs/<slug>.md`：每歌一页（扁平文件即可；若某首歌将来需要随页资源
  ——封面图、拆分多语言块、音频等——再改为同名目录 `content/songs/<slug>/index.md` 的 leaf bundle，URL 不变）。
  front matter 字段：`title`（原题名）、`romaji`（罗马字题名）、`artist`（歌手）、
  `language`（主语言 ja/ko/zh/en）、`source_url`（来源链接，可空）。
- 歌手/专辑归档页将来靠这些字段做 taxonomy，不需返工。
- 界面文案极少（按钮级别），中/日/英任选，不影响歌词数据。
- Hugo 版本基线：最新稳定版（当前示例环境 v0.165）。

## 4. 标注语法与解析规则（核心）

### 4.1 书写语法

- 一行 = 歌词显示的一行；空行 = 段落间隔。
- 汉字串紧跟 `{注音}`；一行可有多个标注；`{注音}` 是**紧贴其前连续汉字串的整体读音**
  （不做任何读音判断，你切到哪里、注什么，显示就是什么）。
  - 整词特殊读法：`明日{あした}`；
  - 逐字标注则拆开：`花{はな}が散{ち}る`。
- 注音只允许假名（平/片假名与长音符等）；不嵌套、不跨行。
- 非日语歌词（韩/中/英）纯文本直出，`{}` 是保留语法禁止使用。

### 4.2 解析规则（shortcode 内实现）

- 注音段 = 汉字串 + 读音；纯文本段 = 假名/标点/空白/外语。
- 词内送假名不标：`食べる` 写 `食{た}べる`；`気まま` 写 `気{き}まま`。
- 校验（errorf，构建报错带行号）：花括号不配对；注音含非假名；`{注音}` 前面不是汉字串。
- 疑似漏标（warnf 提示不阻断）：纯文本段里仍含有汉字。

### 4.3 校对工作流

改歌曲页 `<slug>.md` → `hugo server` 自动重建刷新 → 按「带注音」视图检查；
漏标/错标直接改回源行。无第二处需要修改。

## 5. 渲染与排版

- 日语：逐段输出 `<ruby>文字<rt>注音</rt></ruby>`；注音字号小于正文、颜色略淡；
  行高预留注音空间（`line-height` 设大，避免压行）；字体栈覆盖中日韩。
- 韩/中/英：原文直出。
- 字体策略：v1 系统字体栈；跨设备一致性需求出现时再做 CJK 子集化（决策点）。

## 6. 复制歌词（三种成品）

| 模式 | 内容 | 来源 |
|---|---|---|
| 原文 | 无注音 | 段结构拼文字 |
| 纯假名 | 整行假名（如 一人 → ひとり） | 段结构拼读音 |
| 带注音 | `汉字(注音)` | 段结构拼接 |

实现要点：复制内容由模板**自拼文本**内嵌页面，不复制 DOM（rt 不进剪贴板）。

## 7. 站内搜索（M3，已完成）

- 索引生成：`hugo.toml` 给 home 增加 JSON 输出；`layouts/index.json` 遍历歌曲页，
  lyrics shortcode 在解析时把「纯原文 / 纯假名」全文写入页面 Store（与复制按钮同一份段结构），
  索引条目 = 题名 / 罗马字 / 歌手 / 语言 / URL + 原文 + 假名。
- 检索：`/search/` 页原生 JS（fetch index.json + 大小写不敏感子串匹配 + 命中行摘要），无第三方库。
- 实测：`群れ` / `未来` / `アルペジオ` / `Alexandros`，以及跨注音边界的 `笑えない` / `喜び` 均能命中，
  证明索引确为去注音后的原文。
- 演进（若需要）：命中高亮、按语言过滤、拼音/罗马字匹配、换 Pagefind 等均可后加。

## 8. 构建与部署

- 构建：`hugo --gc --minify`；预览：`hugo server`。
- 部署平台已定 GitHub Pages（M4 接入 Actions workflow + 修改 `hugo.toml` 的 baseURL）。
- 公开站点：meta/OG、robots 策略、每歌来源链接（尊重出处）。

## 9. 演进预留

| 将来想要 | 依据 |
|---|---|
| 注音开关 | CSS 隐藏 rt，不需要第二份数据 |
| 罗马字 | 由段结构读音 + 长音/促音规则生成 |
| 翻译对照 | 同页追加多个 `{{< lyrics lang="…">}}` 块（行对齐届时定义） |

## 10. 风险

1. 人工标注工作量与一致性：无自动兜底；缓解 = 标注规范 + warnf 漏标提示。
2. 版权：全曲公开收录自担；单文件即单歌，删除成本为零；保留来源链接。
3. CJK 字体体积：仅引入 webfont 时才成问题。
