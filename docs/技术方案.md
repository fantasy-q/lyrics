# 歌词展示站 · 技术方案 v6（现状）

> 状态：与仓库当前实现一致（2026-09-04）。本文件讲设计与约定；日常操作见 README。

---

## 1. 架构总览（当前实现）

- **内容层**：每首歌 = `content/songs/<slug>.md`（YAML front matter + 普通 Markdown 歌词正文）。
- **渲染层**（纯 Hugo，无自定义解析器/无构建脚本）：
  - Goldmark **Passthrough**（`config/_default/markup.yaml` 注册行内定界符 `{ }`）
    + 渲染钩子 `layouts/_markup/render-passthrough.html` → `{文字|注音}` 输出 `<ruby>`；
  - 外观 = **Blowfish** 主题（固定提交）+ 少量站点覆盖模板。
- **功能层**：搜索（Blowfish Fuse，Ctrl+K）、按语言切字体、居中排版、页脚构建时间、顶栏 debug 描边开关。

数据流：

> 编辑歌曲 .md（front matter + 歌词）→ `hugo`（passthrough 渲染 ruby + 主题/覆盖模板）
> → 静态站（含搜索索引 index.json）→ GitHub Actions 部署

## 2. 歌词书写规范

- 注音：`{文字|注音}`——两侧**任意字符、任意长度**：`{明日|あした}`、`{食|た}べる`、`{クリア|Clear}`、`{窓|창}外{밖|밖}에`。
- **花括号是保留语法**：无 `|` 的 `{…}` 按字面显示；行内代码 `` `{x|y}` `` 不受影响；正文其它位置勿写 `{…|…}`。
- 分行：单换行 = 一行（`white-space: pre-line` 位于 `& p`）；空行 = 段落（stanza）。
- 歌词块内 **Markdown 语法可用**：`**加粗**`、链接、`<u>下划线</u>`（已开 unsafe）。
- 注意：Markdown 智能引号会把 `I'm` 变 `I’m`；如需关闭需在 goldmark 层处理（未做）。
- front matter schema（示例）：

  ```yaml
  ---
  title: 여명            # 原题名
  romaji: Dawn           # 罗马字题名（标题 <rt> 显示）
  artist: Stellar Blade  # 歌手（header h2）
  language: ko           # ja/ko/zh/en（决定字体族与元数据）
  description: "Stellar Blade — Dawn"  # 搜索 summary 等
  links:                 # 链接列表（显示名按原样）
    - name: 哔哩哔哩
      url: https://…
    - name: Youtube
      url: https://…
  ---
  ```

- 加一首歌：复制任一歌曲 .md → 改 front matter → 写歌词 → `hugo server` 校对 → 推送。

## 4. 渲染与排版要点

- **按语言字体**：页面 front matter `language` → `<article data-lang>` → `font.css` 字体族（ja→Noto Serif JP、ko→KR、zh→SC、其他→Latin）。
- **ruby 注音**：`& p { line-height: 2.2 }` 预留半行距；`rt` 0.6em/900。
- **分行**：`white-space: pre-line` 只放 `& p`（放容器会产生段间幽灵空行，见文末附录）。
- **居中**：body 文本居中 + header/正文列/页脚 `margin: auto`。
- **header**：标题包 ruby（`rt` = romaji）、artist 为 h2、links 为链接列表。
- **footer**：`© {year} {title} · Last Updated: {构建时间}`；Powered by Hugo & Blowfish（英文）。

## 5. 搜索

- 入口：Blowfish Fuse（右上角/Ctrl+K），索引 `index.json` 由站点 `layouts/index.json` 覆盖：
  - `content` = 去注音原文（渲染 HTML 去掉 `<rt>`） + 注音（收集所有 `<rt>`）；
  - `summary` = `description`，缺省取原文首行；
- 已知限制：按注音搜索覆盖「注音部分」（창/밤/わら…）；未注音的假名词尾（如 び、에）不重复收录。

## 6. 字体

- extend-head 加载：Noto Serif 系（拉丁/日/韩/简中，100–900）+ Montserrat / Roboto Condensed（variable，含 italic）。
- 浏览器按 unicode-range 分片按需下载；若 Google Fonts 在部分网络不稳（表现：字重分片失败、回退系统字体），
  备选：镜像源或自托管（未实施）。
- 关掉 webfont：删除 `extend-head.html` 中的链接即可回退系统字体。

## 7. 部署与版本同步

- Actions：`actions/checkout` → clone Blowfish（**固定提交 7ab6a75**）→ `configure-pages` →
  `hugo --gc --minify --baseURL …/` → `upload/deploy-pages`。
- 本地默认 baseURL = `http://localhost:1313/`（`config/_default/hugo.yaml`），生产由 CI 覆盖为 `/lyrics/` 子路径。
- **版本钉定**：Hugo 0.165.0 extended；Blowfish 提交 `7ab6a75`；行尾强制 LF。
- **部署确认**：页脚 Last Updated（构建时间）刷新 = 部署成功。

## 附：本地与线上不一致排查记录（2026-09-04）

### 现象

- 同一份代码，本地 `hugo` 与 GitHub Pages 的 CSS 表现不同（段落间距、字体、行高等）；
- 页面引用的 CSS bundle hash（`main.bundle.min.<sha>.css`）两端不一致。

### 根因

1. **版本漂移**：Blowfish 之前本地与 CI 都是「clone 最新 main」，两端主题提交不同。
2. **行尾符（决定性）**：Windows 上 git `core.autocrlf=true` 把工作区文本转成 **CRLF**，
   CI（Linux）为 **LF** → CSS 源文件字节不同 → Hugo 产物不同 → sha512 指纹不同。
   验证：把本地全部源码（含主题）临时转 LF 后重建，hash 即与线上一致（实测
   `cc8b…` → `76cc…`）。

### 解决办法（已实施）

1. **版本钉定**：Hugo 0.165.0 extended；Blowfish 固定提交 `7ab6a75`
   （本地安装命令与 `.github/workflows/deploy.yml` 的 checkout 行使用同一 sha）。
2. **行尾统一 LF**：
   - `.gitattributes`：`* text=auto eol=lf`（任何平台 checkout 都得到 LF）；
   - 本仓库与 `themes/blowfish` 均 `git config core.autocrlf false`；
   - 克隆主题用 `git -c core.autocrlf=false clone …`。
3. **页脚构建时间**（Last Updated）：每次构建刷新，用于确认线上是否部署了最新构建。

### 日常自查流程

- 两端表现不一致 → 先对比 bundle hash；
- hash 不一致 → 依次检查：
  1. 是否已 push（`git rev-list --count origin/main..HEAD` 应为 0）；
  2. GitHub Actions 最近一次成功是否对应最新 commit；
  3. 本地工作区行尾是否 LF（`.gitattributes` 生效、编辑器别改回 CRLF）；
  4. 浏览器是否缓存旧页（Shift+F5）。

### 经验：`white-space: pre-line` 的作用域

- 放在 **容器**（`.article-content`）上时，goldmark 在段落间输出的换行文本节点
  （`</p>\n<p>`）会被渲染成「幽灵空行」，造成段落间不可控的间隙；
- 应放在 **段落**（`& p`）上：段内单换行保留（歌词分行），段间换行正常折叠；
  段间距用显式 `margin` 控制。
- **CRLF 的隐藏影响**：`pre-line` 把 CR、LF、CRLF 都视作换行——若源文件/模板是 CRLF，
  `\r` 会泄漏进 HTML 文本节点并在 pre-line 下产生「额外换行」（表现同幽灵空行）。
  这也是「本地统一成 LF 后，原本的段落空隙也消失了」的原因；
  歌词源、模板保持 LF（`.gitattributes eol=lf`）不只是为 hash 一致，也是排版正确的前提。
